# مدير الراتب الشهري — v3.8.1

نسخة سحابية وقابلة للتثبيت كتطبيق (PWA) من مدير الراتب الشهري.

## تحديث v3.2.0 — المزامنة الفورية

- بعد تسجيل الدخول تصبح بيانات الحساب هي المصدر الأساسي وتبدأ المزامنة تلقائيًا دون استيراد نسخة احتياطية.
- أي تعديل على الراتب أو الأقساط أو المدفوعات الثابتة أو المصروفات يُحفظ تلقائيًا في الحساب خلال لحظات.
- الأجهزة الأخرى المفتوحة على الحساب نفسه تتلقى إشعار تغيير حي عبر WebSocket وتحمّل أحدث بيانات الحساب تلقائيًا.
- عند الدخول من جهاز جديد تُنزّل بيانات الحساب مباشرة. وإذا كان الحساب السحابي فارغًا ووجدت بيانات محلية قديمة، تُرفع تلقائيًا للحساب مرة واحدة.
- عند انقطاع الإنترنت يستمر الحفظ محليًا، وعند عودة الاتصال تتم المزامنة تلقائيًا وتُعاد قناة المزامنة الحية.
- النسخ الاحتياطية تبقى خيارًا إضافيًا للأمان فقط وليست شرطًا للمزامنة أو لاستخدام الحساب على جهاز جديد.

## تحديث v3.1.1

- إصلاح مسار إعداد حساب المالك لأول مرة مع تشخيص واضح لغياب أسرار Cloudflare وقت التشغيل.
- إعلان `AUTH_PEPPER` و`OWNER_BOOTSTRAP_TOKEN` كأسرار مطلوبة في `wrangler.jsonc`؛ أي نشر مستقبلي يفشل بوضوح إذا لم تكن موجودة.
- اعتماد تحديثات يدوية للتطبيق: الإصدار الحالي يبقى فعالًا حتى يضغط المستخدم **تحديث الآن**.
- إشعار التحديث يحتوي زر **نسخة احتياطية** قبل تطبيق النسخة الجديدة.


## ما الذي يحتويه المشروع؟

- واجهة التطبيق داخل `public/` وجاهزة للنشر عبر GitHub Pages.
- `manifest.webmanifest` + Service Worker + أيقونات للتثبيت على الشاشة الرئيسية.
- Cloudflare Worker داخل `src/worker.js` لتسجيل الدخول ومزامنة بيانات كل حساب.
- Durable Object لتخزين الحسابات والجلسات وبيانات الراتب بشكل منفصل لكل مستخدم.
- حساب مالك واحد بصلاحية `super_admin` مع تبويب **إدارة المستخدمين**.
- طلب إعادة تعيين كلمة المرور ورمز إعادة تعيين مؤقت يصدره المالك.
- نقل آمن للبيانات المحلية القديمة إلى الحساب عند أول تسجيل دخول إذا كان الحساب السحابي فارغًا.

## 1) نشر الخلفية على Cloudflare

ثبّت الاعتمادات:

```bash
npm install
```

أنشئ قيمتين سريتين. لا تضع القيم الفعلية داخل GitHub أو داخل الملفات:

```bash
npx wrangler secret put AUTH_PEPPER
npx wrangler secret put OWNER_BOOTSTRAP_TOKEN
```

- `AUTH_PEPPER`: نص سري عشوائي وطويل لحماية تجزئة كلمات المرور.
- `OWNER_BOOTSTRAP_TOKEN`: رمز سري يُستخدم مرة واحدة فقط لإنشاء حساب المالك الأول.

ثم انشر:

```bash
npm run deploy
```

الإعداد الحالي للواجهة على GitHub Pages يتوقع Worker بهذا العنوان:

```text
https://salary-manager.alromaithi-3bo0d.workers.dev
```

إذا كان عنوان Worker مختلفًا، عدّل `public/config.js` فقط.

### بديل أسهل: النشر من GitHub Actions

أضف الأسرار التالية في **Settings → Secrets and variables → Actions** داخل المستودع:

```text
CLOUDFLARE_API_TOKEN
CLOUDFLARE_ACCOUNT_ID
AUTH_PEPPER
OWNER_BOOTSTRAP_TOKEN
```

ثم افتح **Actions → Deploy Cloudflare Worker → Run workflow**. ملف `.github/workflows/cloudflare-worker.yml` جاهز للنشر اليدوي من GitHub، ولا يعمل تلقائيًا عند كل تحديث حتى لا يفشل قبل إضافة الأسرار.

## 2) إنشاء حساب المالك لأول مرة

بعد نشر Worker افتح التطبيق. إذا لم يوجد مالك بعد سيظهر قسم **إعداد حساب المالك**.

أدخل:

1. `OWNER_BOOTSTRAP_TOKEN` الذي حفظته في Cloudflare.
2. اسم مستخدم للمالك.
3. بريد المالك.
4. كلمة مرور قوية.

بعد نجاح الإعداد يُغلق إنشاء المالك نهائيًا، ويصبح حسابك هو الوحيد الذي يرى **إدارة المستخدمين**.

## 3) نشر الواجهة على GitHub Pages

المشروع يحتوي Workflow جاهزًا في:

```text
.github/workflows/pages.yml
```

عند رفع الملفات إلى فرع `main`، يقوم GitHub Actions بنشر مجلد `public/` على Pages.

للمستودع المقترح `Salary-Manager` سيكون رابط Pages عادةً:

```text
https://irumaithy.github.io/Salary-Manager/
```

من Settings → Pages اختر **GitHub Actions** كمصدر النشر إذا لم يكن محددًا.

## 4) تثبيت التطبيق على iPhone

افتح رابط GitHub Pages في Safari، ثم:

1. اضغط زر المشاركة.
2. اختر **إضافة إلى الشاشة الرئيسية**.
3. أكد اسم التطبيق واضغط **إضافة**.

يوجد كذلك زر **تثبيت التطبيق** داخل الصفحة يعرض الخطوات المناسبة للجهاز.

## 5) طريقة حفظ البيانات والمزامنة

- قبل تسجيل الدخول: يبقى التخزين محليًا كما في النسخة السابقة.
- بعد تسجيل الدخول: تبدأ المزامنة الفورية والمستمرة تلقائيًا ولا يحتاج المستخدم لأي استيراد يدوي.
- كل تغيير يُحفظ في الحساب تلقائيًا ويُدفع إلى الأجهزة الأخرى المفتوحة على الحساب نفسه عبر اتصال حي.
- عند تسجيل الدخول من جهاز آخر بالحساب نفسه تُنزّل بيانات الحساب مباشرة وتبقى متزامنة أثناء الاستخدام.
- إذا كان الحساب السحابي فارغًا عند أول دخول وكانت على الجهاز بيانات قديمة، تُرفع تلك البيانات للحساب تلقائيًا مرة واحدة.
- عند انقطاع الإنترنت يستطيع المستخدم متابعة العمل من النسخة المحلية، وعند عودة الاتصال تتم المزامنة تلقائيًا وتعود قناة التحديث الحي.
- الاستيراد من نسخة احتياطية أداة استرجاع اختيارية فقط وليست جزءًا من مسار تسجيل الدخول أو المزامنة.

## 6) إعادة تعيين كلمة المرور بواسطة المالك

1. المستخدم يفتح **نسيت كلمة المرور** ويرسل طلبًا للمالك.
2. يظهر الطلب في تبويب **إدارة المستخدمين** لدى المالك فقط.
3. المالك يضغط **إنشاء رمز إعادة تعيين**.
4. يظهر رمز مؤقت يُعطى للمستخدم.
5. المستخدم يدخل اسم المستخدم/الإيميل + الرمز + كلمة مرور جديدة.
6. الرمز يُستخدم مرة واحدة وتنتهي صلاحيته تلقائيًا، وتُلغى الجلسات القديمة للحساب بعد إعادة التعيين.

## 7) ملاحظات أمان

- لا تحفظ `AUTH_PEPPER` أو `OWNER_BOOTSTRAP_TOKEN` داخل المستودع.
- صلاحيات المالك يتم التحقق منها في Worker نفسه، وليس عبر إخفاء التبويب فقط.
- كلمات المرور لا تُخزن كنص صريح.
- ملف `.dev.vars` مستبعد من Git بواسطة `.gitignore`.

## الملفات الرئيسية

```text
public/index.html              الواجهة الرئيسية
public/config.js               عنوان Worker عند استخدام GitHub Pages
public/manifest.webmanifest    تعريف PWA
public/sw.js                   التخزين المؤقت والعمل كتطبيق
src/worker.js                  الحسابات والمزامنة وإدارة المستخدمين
wrangler.jsonc                 إعداد Cloudflare Worker / Durable Object
.github/workflows/pages.yml    نشر GitHub Pages تلقائيًا
.github/workflows/cloudflare-worker.yml  نشر Worker يدويًا من Actions
```
